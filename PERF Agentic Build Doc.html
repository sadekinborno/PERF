1. Phase 1 — Proposed Methodology (confirm below, then lock it)

The Four PERF Re-Annotation Strategies

  1. Zero-Shot Direct — model labels the text cold, no examples, no reasoning shown. Baseline raw judgment.
  2. Few-Shot Exemplar-Guided — model sees 3–5 labeled examples per class (held out from the eval set) before labeling. Tests whether grounding shifts the label.
  3. Chain-of-Thought (CoT) — model reasons step by step before committing. Surfaces ambiguity the direct methods miss.
  4. Rationale-Then-Critique — model gives its zero-shot label, then is shown that label and prompted to critique it against the dataset's specific documented failure mode (e.g. "could this be the dampening effect?" for SST-5, "does this hinge on the neutral–contradiction boundary?" for SNLI). This is PERF's signature strategy — it's what makes the audit targeted rather than generic re-labeling.

Ensemble — budget tier

Given a student budget (not unlimited credits), use the cheap/mini tier from 3 providers, not frontier models — provider diversity matters more here than raw capability, and mini-tier models run roughly 10–50x cheaper. Think Claude Haiku-class, a GPT "-mini" model, and a Gemini Flash-class model (exact current names/prices change — check each provider's live pricing page before locking this in, don't trust a remembered number). Avoid any "extended thinking"/reasoning-mode variant for the simple strategies (zero-shot, few-shot) — those silently bill extra internal reasoning tokens even on short classification prompts.

Reality check: at mini-tier pricing, a demo-scale run (dozens to ~100 short tweets, mostly single-pass) should land in the low single-digit dollars, not tens of dollars — but always run the cost estimator (Prompt A) before spending anything for real.

Voting / Aggregation

  • Each (model × strategy) pair → 12 votes per example, each with a self-reported confidence (0–100, elicited in-prompt).
  • Final PERF label = confidence-weighted majority vote across all 12.
  • A label is flagged (disputed) if the PERF label ≠ gold label and ≥60% of weighted votes agree with the PERF label (strong ensemble consensus against gold, not noise).
  • Anything below that threshold → "uncertain," reported separately, not counted as a disagreement.

Metrics

  • Overall agreement rate (PERF vs. gold)
  • Flag rate (% disputed)
  • Per-strategy agreement (does CoT catch more than zero-shot? does rationale-critique catch more than plain few-shot?)
  • Qualitative cross-check: do flags cluster where the literature already says they should (extreme classes in SST-5, neutral/contradiction boundary in SNLI, etc.)? This is your strongest validation story for the defense.

Cost-Efficient Two-Stage Execution

Running all 12 (3 models × 4 strategies) votes on every example is the expensive way to do this. Instead, cascade:

  • Stage 1 (cheap): run only Zero-Shot across all 3 models on the full sample — 3 calls/example.
  • Stage 2 (targeted): only escalate to Few-Shot, CoT, and Rationale-Critique for examples where Stage 1 already shows disagreement (between models, or against gold). Most examples should agree in Stage 1 and never need the expensive strategies.

This isn't just a cost hack — "cheap first pass, expensive scrutiny only where the ensemble already disagrees" is a legitimate scaling argument for PERF, and a good line for the defense: it's how you'd eventually audit all 10 datasets without burning the department's budget.

Sampling

  • Full study (post-Monday): stratified random sample per dataset, size scaled to dataset size and remaining budget.
  • Demo scope for Monday: start with 30 examples from iSarcasm as a cheap sanity-check run — catches bugs before you spend more. If the pipeline and numbers look right, scale to 60–80 examples for the version you actually present. If budget allows, a 40–50-example partial run on SemEval-2016 Task 6 to show generalization.

3. Agent Prompts (copy-paste into Antigravity)

Prompt A — Pipeline scaffold (Phase 2)

Build a Python project called perf-pipeline for an NLP annotation audit tool, with cost
control as a first-class requirement (student budget — not unlimited credits).

Structure:
- data/ : loaders for CSV/JSON datasets, each returning (text, gold_label, metadata)
- strategies/ : four prompt-builder functions — zero_shot(text), few_shot(text, exemplars),
  chain_of_thought(text), rationale_critique(text, known_issue_description) — each returns a
  prompt string for a given task's label taxonomy
- models/ : a thin wrapper client per provider (use environment variables for API keys, never
  hardcode secrets), each with a .label(prompt) -> {label, confidence, raw_response, tokens_in,
  tokens_out} method. Default to mini/budget-tier model names, not frontier ones.
- voting/ : a confidence-weighted majority vote aggregator that takes a list of
  {label, confidence} from all (model x strategy) pairs and returns
  {final_label, agreement_pct, flagged: bool} using a configurable flag threshold (default 0.6)
- run.py with a TWO-STAGE cascade:
  Stage 1: run only zero_shot across all configured models on the full sample.
  Stage 2: for examples where Stage 1 votes disagree (across models, or vs gold if available),
  escalate to few_shot, chain_of_thought, and rationale_critique for those examples only.
  Log how many examples needed Stage 2 vs. stopped at Stage 1.
- A --estimate-cost flag: before spending anything, estimate total tokens for the planned run
  (Stage 1 for all examples + Stage 2 for an assumed worst-case escalation %) using per-model
  $/M input and output rates from config.yaml, and print the projected cost. Require an
  explicit --confirm flag to actually spend money after seeing the estimate.
- A hard budget cap in config.yaml (max_spend_usd): track running cost as it goes and stop
  cleanly, saving partial results, if the cap would be exceeded.

Add basic error handling and rate-limit backoff for API calls. Write a short README documenting
the cascade logic and the cost controls.
